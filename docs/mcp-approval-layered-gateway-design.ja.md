状態：API 0.6第12〜13節まで接続合意済み。[具体型・DB・処理順序](mcp-approval-v06-implementation.ja.md)を確定し、実装中。本文の論理型は同書の具体型へ対応する。常駐配備・実接続受入は未実施。

正本：[責務再整理](../../codex-hoshikage-proxy/docs/mcp-approval-layering-revision.ja.md)。旧[0.5詳細設計](mcp-approval-v05-gateway-design.ja.md)のうち、旧wire固有の制約は後継へ流用しない。

## 1. 独立した三つの判断

| 判断 | 根拠と担当 | Gatewayの動作 |
| --- | --- | --- |
| 誰に表示できるか | Proxyの公開範囲情報＋Gatewayの本人・会話認可 | 公開または同じ会話の本人向け。判定不能を公開へ倒さない |
| 今回だけ許可できるか | Proxyが確認した上流承認、call、全引数、不変の確認対象、現状態、適用中の禁止規則 | 全表示確定後に単発ボタン。意味評価済みを必須にしない |
| 依頼中許可できるか | 明示選択されたポリシー、その版・実効適用、呼出しごとの適格性 | 適格な場合だけ別ボタン。単発から自動昇格しない |

説明辞書がないことと、全引数がないことを区別する。前者は汎用表示、後者は許可不可。公開できないことと、操作が禁止されていることも区別する。拒否は現在のinteractionへの独立操作とし、内容取得・全ページ表示を前提にしない。

## 2. Adapterと内部型

- `ExecutionBinding`：Proxy instance/recovery、認可主体、会話、Run、Response/Turn、callとrevisionを照合する内部型。
- `DisplaySnapshot`：表示先、版、期限、完全性、ページ、型を保持した全引数、任意の補助説明。APIの生JSONをそのまま公開rendererへ渡さない。
- `PolicySelection`：未選択または明示選択した登録済み識別子・版。要求時に永続固定する。未選択を空文字や架空の世代で表現しない。
- `EffectivePolicy`：Proxyが返した実効適用結果と、運用者により強制された規則。要求値と別に保存し、単に同じIDが返っただけで適用成功と推測しない。
- `ApprovalEligibility`：単発可否、依頼中可否、理由を別々に保持する。意味未評価を一括の「許可不可」へ変換しない。

各内部型への変換はAPI版別adapterで行う。従来版の必須tool_policyやpolicy世代を後継の未選択実行へ捏造しない。具体的なoptional/null/enumはAPI 0.6と実装詳細書で確定した。未知API版を都合よく旧版へ縮退解釈しない。

## 3. 汎用表示とUX

通常の公開可能な操作は最初から操作名・サーバー・全入力・選択肢を元会話に表示する。日本語の補助説明がある場合は併記するが、実引数を置換しない。説明が未評価なら「この操作の意味・安全性は評価していません。実際の入力内容を確認して選んでください」と示す。

型付きの階層表示で、キー、文字列、数値、boolean、null、空配列、空object、順序を保持する。数値を浮動小数点へ丸めて別の値にしない。キー順以外の構造を勝手に正規化せず、同名キーなど忠実な表現ができない応答は契約違反として許可しない。未指定のフィールドを推測で追加しない。コードやMarkdownを実行・展開しない。

秘密・公開可否未確認は「自分だけに表示して確認」。未知の意味だから秘密と説明しない。Proxyが指定した非機密長文の本人向けページも長さを理由として扱う。通常操作を全て本人向けに戻すことを完成条件にしない。

単発適格なら「今回だけ許可／拒否」、ポリシー適格なら「この依頼中、このツールを許可」を追加。禁止規則が適用される場合は理由と拒否を表示し、別ツール・別編集方法へ自動変換しない。未知のエラーを「利用者が拒否」と表示しない。

## 4. 選択・適用と永続化

表示profile、要求ポリシー、作成されたgrantは別の記録にする。Gatewayが選ぶ初期ポリシーには合意済みのNotion部分置換禁止を含めるが、正式識別子はevaluated-turn-notion-guard/version=1で、表示指定とは別のapproval_policyフィールドに固定する。表示を選んだ副作用としてポリシーを適用しない。

実行開始前に要求ポリシーを固定し、受付の冪等照合へ含める。Proxyの実効適用結果を照会・保存し、不一致や不明時は新規の許可処理を止める。適用失敗をポリシーなしの再送で補わない。結果不明の実行をもう一度作らない。

同一会話で次Runのポリシーが変わる際のruntime切替と文脈維持はProxyの責務。Gatewayが新しい会話を作って代用しない。過去のRunのprofile・選択・grantを次Runへ移植しない。

0.5のschema9案を置換し、0.6のmigration9へ整理した。既存schema8の履歴と旧profileを維持する。表示証跡・返信意思・固定操作キーの設計は継承するが、全scopeにpolicy世代必須という条件は版別にする。本文・秘密の無鍵digest・Discord tokenを永続化しない。

## 5. 継承する保証

0.5詳細設計の次の保証を維持する。具体APIの上限・返信項目名だけは後継契約へ合わせ、旧値を新契約と称しない。

- ページとDiscord投稿を分離し、内容を省略せず全配信確定後だけ許可する。
- action別検証。拒否は本人・会話・現在のinteraction/revisionを確認し、許可用tokenや全ページ表示を要求しない。
- ACKを先に行う。成功時に不要な本人向け完了通知や新Threadを作らない。
- 冪等な意思保存と同じoperationの照会。未知結果を新しいPOST・AI再実行で補わない。
- 公開投稿は再照合、本人向けは再起動後に明示再表示。版・対象・世代が違う押下は引き継がない。
- 新規Turn枠・表示取得枠と、停止・拒否・取消を分離。独立した期限回収とSupervisor。
- 非MCP承認でも、コマンド・変更一覧の部分表示で許可しない。

## 6. 機能単位の開始条件と受入

| 機能 | 実装前に確定するもの | 受入 |
| --- | --- | --- |
| 汎用表示・単発承認 | 後継表示型、完全性、単発適格性、非公開理由、返信・エラー、版別DB | 未評価ツール・未知キーも全入力表示、単発のみ可。欠落・別callは不可 |
| 配信・復旧 | 上記snapshotへの拘束、ページtoken、配信証跡、拒否独立経路 | 長文、途中失敗、別人、再起動、応答喪失、拒否、二重押下 |
| ポリシー選択・依頼中許可 | 選択と実効結果、scope、runtime分離、失効、初期ポリシー範囲 | 選択失敗で縮退なし、別Runに非流用、Stop/Steer失効、未選択クライアントへの非波及 |
| 説明・ポリシー範囲の拡張 | 当該ツールの評価規則と肯定・否定例 | 意味と作用、説明と実入力の対応、危険な後続引数の非自動許可 |

全342件の評価完了はどの汎用機能の開始条件にも置かない。台帳は「完全表示できる」「補助説明がある」「依頼中許可の対象」を別軸で示す。個別の説明未評価を全体の表示障害にしない。

接続契約は確定済み。型・Store→表示・単発返信→復旧→ポリシー接続の順に実装する。各機能の設計・契約・受入条件を先に完成させる。実Codexの承認到達、Discordでの内容・押下、実行結果は別々に実証する。配備と英日マニュアルは受入後。

## 7. 後継APIの照合項目（0.6で解消済み）

下記はAPI 0.6第12〜13節までの接続レビューで解消済み。具体型と接続は0.6実装詳細書に従う。

1. 汎用の型・全引数・補助説明・公開可否・単発適格性の応答。意味未評価と取得不完全の別理由。
2. ポリシー識別子・版の選択、強制規則、実効結果、未選択scope、capabilityとエラー。
3. 表示版・ページ完全性と返信の結び付け。旧版で禁止を迂回できず、未選択実行へ禁止を波及させないこと。
4. 既存会話継続、runtime互換性、同時実行、再起動・正式復元、設定変更時の扱い。

上記の接続契約は確定した。以後は合意したwireを使い、実Proxyのruntime分離と実Discordの受入を確認する。コードの完成と常駐環境への反映は分けて記録する。
