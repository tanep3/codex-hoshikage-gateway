## 受け入れられる方針

- 通常操作は元会話に内容を最初から示す。通常操作の未対応をプライバシー保護と説明しない。
- 本人向けの例外は元会話のephemeral表示を使い、DMへ移動させない。
- 単発許可と依頼中のツール許可を区別する。後続呼出しの引数・作用もProxyが評価し、削除・外部送信・任意実行等を既存許可で通さない。
- 全カタログを有界・非同期で取得し、取得障害、意味未評価、本人向け表示を別の状態として返す。

## R-01 新scopeと既存照会APIの接続を確定する

対象：API第3・6・7・8節、既存0.3のoperation／interaction／mcp-grants契約。

第6節はscopeへ `policy_generation` と `definition_generation` を追加する。一方、新しいpresentationの例には完全なscopeがなく、既存operation・interaction内のoperation・許可一覧での追加フィールド、適格性、旧版との関係は具体化されていない。

現Gatewayは `src/mcp_grants.rs` の `canonical_scope` で旧scope項目だけを抽出し、`src/mcp_inline.rs` はoperationの適格性とpresentationを照合する。このままでは追加世代を保存・比較できず、新policyと旧allowlist由来の適格性を混用するおそれがある。Gateway側も変更が必要である。

Proxy側への追記依頼：

1. 0.5 Responseに対するoperation、interaction内メタデータ、grant一覧の完全なJSON例を示す。新世代の位置・必須性・取得不能時のnull条件を固定する。変更しない応答については、その旨と新情報を取得する正本を明記する。
2. 0.5のボタン判定で正本とする適格性を定義する。presentationのactions／tool_policyと旧operationの `turn_grant_eligible` が異なり得るか、異なる場合に何を使うかを明記する。
3. 新capabilityと既存のdetails／turn capabilityとの依存関係、設定省略時の新policyが0.3／0.4 Responseへ適用されるかを定義する。旧契約維持と整合する例を追加する。
4. 作成済み許可の一覧から、適用policyと範囲をGatewayが復元できるようにする。新旧Response混在・再起動・取消の試験で確認する。

これは内部実装を指定する依頼ではなく、Gatewayが保存・表示・照合する境界の確定依頼である。

## R-02 カタログの正常更新をまたぐ後続呼出しの動きを確定する

対象：カタログ設計第4・5節、API第7節。

カタログは30秒でstaleとなり、その間は自動許可不可。同一定義の再取得成功時には元grantを延長せず維持する設計になっている。ただし、stale中に到着した後続呼出しについて、更新後に既存grantで再評価するのか、その呼出しは改めて利用者の押下を待つのかが明記されていない。

推奨する追記：

- stale中はその呼出しを有界に保留し、確認を連投しない。
- 同じ世代・定義の正常な再取得後、まだ有効な既存grantをProxyが再照合して適用できる。Gatewayが新たな許可を自動送信する方式にはしない。
- grant期限切れ・停止・Steer・世代変更・取得失敗の場合は自動適用しない。失敗前のgrantを復活させない既存規則を維持する。
- 利用者の拒否や手動許可との競合は既存の送信意思境界で直列化し、適用は1回にする。
- 「依頼中許可→30秒経過→同じ通常操作→同一定義で更新成功」を受入へ追加し、単なる正常更新で確認が繰り返されないことを確認する。障害後の再確認とは区別する。

## Gatewayが担う設計・実装

以下はProxyだけに修正を求める事項ではない。API合意後、要件・システム設計・DB設計へ具体化してから実装する。

- 4800 UTF-16 unitsのdisplayを既存の短い通常投稿へ単純連結しない。Discordの実送信形式を決め、ラベル・補足・エスケープ後の容量を検証する。必要な分割では全断片の配信成功を、そのページの表示成功の条件とする。本人向けへ切り替えるだけで容量問題が解消した扱いにしない。
- 公開の通常操作は最初のカードで判断できるようにする。長文や本人向けページは省略せず、全ページ表示前に許可ボタンを有効にしない。
- ページ／断片の配信記録、本人・会話・Response・版・トークンを対応付ける。本文や秘密値の無鍵ハッシュをDBへ保存しない。
- 未確定配信を表示済みと数えない。再起動後に確認できない本人向け表示は、新しい本人操作による再表示から再開する。古い押下を新しい内容の許可へ引き継がない。
- 0.3／0.4／0.5のResponse別処理を分離し、旧renderer一覧や旧適格性を0.5へ流用しない。
- MCP以外の承認でも、コマンドや変更内容を途中で切ったまま許可できる既存問題（全体監査G-01）を修正する。
