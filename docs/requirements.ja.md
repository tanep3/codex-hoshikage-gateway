# Codex Hoshikage Gateway 要件定義書

版: 2.5 / 2026-09-16
著作者: Tane Channel Technology / MIT
基準: [Proxy API v2 契約案0.2](../../codex-hoshikage-proxy/docs/workspace-artifact-api-v2.ja.md)。契約レビュー承認済み。実装・受入・配備済みを意味しない。

## 1. 目的と利用者

DiscordからCodexへ話しかけ、作業を依頼し、成果物を受け取れる製品を提供する。実行先や内部IDを利用者に登録・記憶させない。初版の利用者は許可した本人1名、許可Guild内。Rust、SQLite、MIT配布、英語を主とする英日README・導入・ユーザーマニュアルを維持する。

本版は旧版のProject登録、Gateway cwd管理、共有ワーク既定、全体1実行、成功Responseのみの継続、通信切断による中断、成果物直読、回答再取得不可を置換する。旧記述を実装根拠として併用しない。

## 2. 責務

| Proxy | Gateway |
| --- | --- |
| 会話・ワーク自動割当、継承、権限、実行・競合制御 | Discord認可、会話対応、受付・キュー、全体2実行 |
| App Server所有、モデル実行、専用成果物登録ツール | モデル選択、承認、Steer、停止UI |
| 成果物と確定回答の保存正本、一覧、照会、本体取得、有限リース | 成果物選択、配信先、配信状態、キャッシュ、復旧 |
| 復元世代、監査付きUNKNOWN占有解除 | 世代不一致の受付保留、Proxy解除状態の照合 |

Gatewayにcwd・許可ルート・Project登録を要求せず、Proxyのファイルを直接開かない。同居・別ホストとも認証付きHTTPを使う。GatewayからProxyの権限・sandbox・サービスを変更しない。Discord ID・Bot tokenをProxyへ送らない。

## 3. 会話と操作

- 通常チャンネルはチャンネル単位、Discordスレッド・フォーラム投稿はそれぞれの場所単位で履歴を持つ。フォーラム全体を1会話にはしない。
- `response_mode`で全投稿／Botメンション時のみを選ぶ。Bot自身、他Bot、Webhook、許可外ユーザー・Guildを除外する。
- 初期モデルは設定を継承する。候補が複数なら選択UIを出す。`/models`は一覧、`/model`は選択確認／変更。変更は次のTurnで反映し、同じProvider内の履歴を保つ。
- 新規会話は独立したProxy会話作成APIを使う。ワークはProxyが自動割当し、初回失敗・中断後も既知の会話とワークで継続可能。開始結果不明なら保留する。
- 共有は認可済みワークを表示名で明示選択する。既存会話のワークを黙って変更しない。ディレクトリ分割をマルチテナント隔離とは説明しない。
- 通常返信は回答本文を中心に表示する。依頼ID・COMPLETED・配信完了などの定型文を毎回付けない。状態・対処が必要なときだけ短く案内する。

## 4. 実行・停止・復旧

| 操作 | 要件 |
| --- | --- |
| 受付 | Discord Message IDで重複排除。検証予約を先に永続化し、本文・添付は同一性を検証 |
| 待機 | 同一会話FIFO、全体2実行。同一／包含ワークの全クライアント排他はProxyが担当 |
| 実行 | Proxy v2の202は永続受付であって開始成功ではない。会話IDで実行し、前回成功Responseへの依存を廃止 |
| 途中表示 | SSE deltaは暫定表示。確定回答の保存状態を照会し、保存済み本文で最終表示を確定 |
| `/stop` | 先に会話pauseを保存。元要求キーでProxyへ停止し、Turn IDがなくても停止意思を伝える |
| 開始前停止 | 元要求より停止が先着しても取消予約で遅着実行を禁止。Gatewayは停止完了を推測しない |
| `/resume` | 待機列だけ再開。取消済み要求を再実行せず、UNKNOWN・世代不一致・権限を解除しない |
| Steer・承認 | 指定Turn／承認IDを再照合。実行・コピー枠の外で処理。結果不明時に無条件再送しない |
| 再起動 | 未送信入力はDiscordから再取得・照合。送信済みは保存したキー・IDで照会し、AIを自動再実行しない |
| 接続断 | v2実行は接続から独立。Gateway切断を停止成功と扱わない。停止意思は永続記録から復旧 |

Gateway送信境界はDB commitを先行する。Proxy受理後の処理進行と、Gatewayによる実行要求の再送を区別する。操作照会404は未実行の証拠にしない。処理枠が埋まっていても停止・承認・Steer・状態照会を可能にする。

会話を始める前の `/workspace` で、Proxyが許可した共有候補をページ送りして選べる。通常は選択不要で専用ワークを自動割当する。自動作成と手動選択が競合しても、一度決まった作業先を置換しない。`/new` は通常チャンネルとフォーラム投稿内から新しい会話を作れる。タグ必須フォーラムではDiscordの投稿作成画面へ案内する。

## 5. 成果物と回答

`/get`は登録済み成果物を名前・版・サイズ・日時・期限で選択する。相対パス指定も可能。一般成果物の登録は実行に紐づく専用ツールまたは本人の明示パス操作とし、生成画像には後述の自動登録・配信を適用する。Gatewayは、モデルの文章・diff・フォルダー探索を配信指示にしない。登録されたことと配信を許可したことは別。

選択画面は1ページ25件、10分間有効とし、期限後は一覧の開き直しを案内する。会話・Proxy世代・表示時点の候補との照合を行い、再起動しても有効期間内の対応を復元する。

ProxyがREADY公開したartifact_idは不変の保存版を指す。再送は同じIDを使い、新版取得は新しい作成操作とする。作成応答喪失時は同じ操作を照会し、新しい原本のコピーで埋め合わせない。実行中・失敗・中断だけを理由に取得を禁止しない。原本の原子的snapshotと保存コピーの不変性を区別する。

Gatewayは配信待ち→有限リース→本体取得→サイズ・ハッシュ検証→送信意思→Discord送信→結果保存の順に処理する。結果不明は照合し、自動で別投稿しない。temp消失後も期限内なら同じ成果物を再取得する。期限・権限撤回・破損を区別する。キャッシュ削除やリース解放はProxy原本削除ではない。

保持期限の延長はファイル取得・Discord配信から独立して処理する。Proxyの時刻と最大保持期限に従い、延長要求が結果不明なら同じ操作を照会する。延長の受付だけで保持成功と表示しない。

確定回答はProxyが保存してからoutput_ready通知を行う。実行完了・回答保存・Discord配信を別状態にする。Gateway DBに本文を重複保存しない。回答にも有限リースを取得し、再起動後は同じResponse IDの確定本文を回収する。保存失敗や途中回答を完全な最終回答と偽らない。

再送は `/retry` で対象を選び、重複表示の可能性を確認してから行う。元の配信記録を保持し、新しい配信記録から同じresource ID・サイズ・ハッシュを参照する。送信途中と再送への切替は排他し、確認ボタンの重複で二重に予約しない。失効・破損・権限撤回を「再送すれば直る」と案内しない。

共有ワーク一覧は `/get scope:shared` の明示操作に限る。会話一覧の既定範囲を黙って広げない。転送再開は同じID・強いETag・正確なContent-Range・最終SHA-256一致を必須とし、原本から新しいコピーを作らない。

## 6. 安全性・運用の不変条件

1. Message ID・実行要求キー・Proxy会話／Response／Turnの対応を取り違えない。
2. UNKNOWNと配信失敗をAI再実行で解消しない。
3. 同一会話は同時1実行。Gateway全体2、Proxyのワーク排他も満たす。
4. 停止意思受付と停止完了を分ける。遅着した停止を別Turnへ転送しない。
5. DBが書けなければ副作用開始を止める。critical task異常を放置しない。
6. 起動・再接続・送信直前にCapabilityとインスタンス・復元世代を検証する。v1へ黙ってフォールバックしない。
7. 復元世代不一致では新規受付停止。新世代を黙って信頼せず管理照合を必要とする。
8. UNKNOWN占有の例外解除はProxy運用者の監査付き管理操作。Gateway側の解除でProxyを迂回しない。
9. 解除後の旧会話は隔離し、同じワークの明示的新規会話を選ぶ。遅着実行を再検出したら再保留する。
10. 正式復元で世代を更新する。任意の全ディスク巻戻しの必須検出は保証しない。
11. ログ・Discordに秘密・絶対サーバーパス・生上流エラーを出さない。tempと認証ファイルは本人だけが読める。
12. 検証worker消失でも期限切れVALIDATINGを独立回収。後着結果はversionで破棄。

## 7. 設定・配布・移行

実行バイナリは `codex-hoshikage-gateway`。`cargo install --path . --locked`で導入する。Cargoのインストール先設定を上書きしない。Rust・SQLite、Ubuntuのsystemd user serviceを基本にする。

configはTOML。Discord本人・Guild・応答モード、認証ファイル、Proxy URL、モデル、状態・temp・容量を設定する。サンプルに使える正の標準値を入れ、容量の初回入力を要求しない。Proxy候補値は測定後に同梱値と整合させる。Discord制限とは別に管理する。

旧会話・旧要求・原本は削除しない。旧ワークを自動割当へ無断移動せず、確実な対応だけを明示移行する。不明な旧記録と旧送信待ちは隔離し、自動再送しない。migrationは既知schemaのみ前進、transaction・rollback、未知の新schemaでは書込前に起動拒否。正式バックアップ／復元、DB外マーカー、監査付き復元解除を維持する。

README・導入・マニュアルは英語主、日本語リンク付きで、製品説明・導入・使い方を分ける。実装済み・Mock検証・実モデル・Discord結合・配備を区別し、未完成のビルドを本番更新として案内しない。

## 8. 受入条件

| ID | 合格条件 |
| --- | --- |
| A-01 | 許可された通常チャンネル・スレッド・フォーラム投稿で登録不要の会話。全投稿／メンション設定と認可を検証 |
| A-02 | モデル一覧・変更・初期設定継承・複数候補選択・変更後の履歴維持 |
| A-03 | 会話作成応答喪失・初回失敗・再起動で同じ会話／ワークを照会。別ワークを作り直さない |
| A-04 | 202受付と開始・完了を区別。Message ID重複、dispatch前後クラッシュで二重実行なし |
| A-05 | 2実行並列と同一会話FIFO、共有・包含ワーク競合、CONTROL枠独立 |
| A-06 | 停止先着・202応答喪失・開始中・自然完了競合・重複停止・再起動で指定要求だけ停止 |
| A-07 | pause永続化、pause中受付、resume後だけ待機開始。取消／UNKNOWNを再実行しない |
| A-08 | Steer・承認の対象・期限・重複・結果不明を検証 |
| A-09 | 実モデルの作成→専用登録→一覧→選択→受信。登録失敗を成功表示しない |
| A-10 | 同一artifact IDの原本更新／削除後再取得で同じハッシュ。新版操作と区別 |
| A-11 | 実行中取得、パス差し替え・特殊file・容量・権限撤回・破損・期限切れ |
| A-12 | リースとGC競合、延長上限、解放重複、容量不足、低速別ホスト |
| A-13 | 確定回答保存失敗と実行完了を区別。再起動後に同じ回答を取得・配信 |
| A-14 | Discord POST/PATCH応答喪失、キャッシュ消失、権限変更で重複投稿・AI再実行なし |
| A-15 | 世代不一致・復元中クラッシュ・旧DB・欠損で隔離、ID再割当なし |
| A-16 | UNKNOWN管理解除後の旧会話隔離・明示再利用・遅着実行再検出 |
| A-17 | worker消失・DB故障・critical task終了で受付停止。validation期限を独立回収 |
| A-18 | 旧設定・DB移行とバックアップ整合、未知schema拒否、実測した既定値と文書一致 |

Proxy復元の管理操作は `admin proxy-inspect` と `admin proxy-accept` に分ける。5分以内の照合票・理由・明示的なリスク受入が必要。保存世代と現世代、会話・要求・操作・成果物・リースを再照合し、不明な旧要求は自動再送しない。別instanceへはこの操作で付け替えない。旧会話からの移行は `/new` で会話を作り、必要なら `/workspace` で許可された共有先を選ぶ。旧原本と旧記録は保持する。

完全な409 busy応答で開始拒否が確定した依頼は失敗として表示する。AI要求の送信回数を増やす待機復帰はしない。成果物コピー枠の429 `repeat_same_request` は同じ操作キー・本文でのみ再試行できる。応答喪失後の404では再試行しない。

API契約で定義された操作状態・エラー・リース・復元手順も受入対象。機能の実装状況と残作業は[実装状況](implementation-status.ja.md)へ記録する。

通常投稿の受付に `/new` を要求しない。開発中の旧記録だけが残り、Proxy会話が未作成で、過去の依頼がすべて終了確定・占有なしの場合は、同じDiscordの場所で次の新規投稿から会話を自動初期化する。過去の依頼の再送・履歴の削除は行わない。明示停止、復元保留、実行中・結果不明の保護は解除しない。既存のProxy会話を失った場合に履歴を黙って破棄することも禁止する。

## 生成画像の自動配信

[確定した生成画像配信仕様](generated-image-delivery-contract.ja.md)を適用する。通常の画像作成依頼に対し、Proxyが帰属を確定して登録したPNGを依頼元へ自動添付する。回答本文とは独立した監視・配信状態を持ち、schema 5のwatch/item/claimで永続化・重複抑止する。一般成果物の無差別送信は許可しない。/getは必須ではなく、明示再添付は /retry で確認する。

### 2026-09-13 操作・進捗表示の補正

画像の登録・配信待ちが続く場合は、準備状況を同じ案内の更新で表示する。モデル未選択時に限らず `/model` から選択メニューを開ける。送信処理中の未受理照会を結果不明の根拠にせず、正常な状態の確認後は既存の警告を削除し、正常復帰の投稿はしない。

### 2026-09-15 承認・最終回答・処理中表示

承認内容は目的・実行内容を人が読める形で表示し、内部IDや生JSONを本文に出さない。承認後は同一カードの操作ボタンを無効化し、送信確認と作業完了を混同しない。確定回答を会話末尾へ投稿し、途中表示を安全に削除する。実行中は標準typing indicatorを表示し、承認待ち・終端・UNKNOWNでは継続しない。

承認ボタンの正常処理では本人専用の追加メッセージを作らず、元の承認カードだけを更新する。処理エラーは本人に通知する。

## MCP承認・入力（2026-09-15追加）

Proxyのinteraction relay契約に従い、flat-primitives-v1のmcp_formを扱う。通常承認とは別の永続ID・revision・操作キーを使い、空フォームのツール許可も明示操作で行う。serverNameと承認文面を全文表示し、入力は本人専用画面で行う。string/integer/number/boolean、required、enum、上下限を検証し、defaultで自動回答しない。その他の対話種別は宣言しない。

独立した定期照会で未解決の対話を復旧する。終了・期限切れ・結果不明・世代不一致のボタンは操作不可。回答意思を本文の永続保存なしに記録し、切断時は同じ操作キーを照会する。利用者停止、明示拒否、対話未対応、期限切れ、上流障害を区別し、モデルの文章を利用者拒否の証拠としない。

## エラー案内の利用者向け要件

エラー案内には、確認できた状況と利用者が次に行う操作を含める。自動照会中は「操作せず待つ」、解消しない場合の確認先と明示再送の手順を示す。実行・保存版取得・Discord送信結果不明を区別し、原因不明を接続障害と断定しない。設定変更が必要な場合は運用者への依頼と明記する。配信完了または明示再送への切替後は古い取得警告を安全に除去し、復旧成功の投稿を追加しない。

ファイル変更の承認はProxyの `changes` と `paths` の両形式を表示対象とする。空・不正な対象一覧では承認を許可しない。承認ボタンを出せないカードに「今回のみ承認」の操作説明を付けず、取消と運用者への連絡を案内する。

## MCP承認の操作表示と作業ターン限定許可（2026-09-16 方針合意）

本節は旧来の「MCPは毎回個別許可」の方針を拡張する。具体APIは双方合意版0.3で確定した。上流対応付けの実証と常駐利用可否は別途記録する。

- MCP承認は認証情報の入力とは区別し、何をする操作かを判断できるようにする。確認原文・実引数/コード・翻訳/要約を区別し、秘匿・省略・取得不能を明示する。文面から権限・安全性・同一性を推測しない。
- 「今回だけ許可」と「この依頼中、このツールを許可」は独立した明示操作。後者は引数変更を含む範囲を表示し、1 Agent Run/1 chat turnに限定する。別利用者・別Discord会話・別依頼・並列Runに流用しない。
- 同一Proxy Response/Turn・MCPサーバー設定世代・ツール・依頼内容世代・許可範囲を検証する。Proxyは許可の正本・適用・監査を管理し、Gatewayは本人確認・表示・選択・依頼との対応を管理する。
- browser_run_code_unsafe は常に個別確認。browser_evaluate は実証対象とし、評価未完了・識別不能は個別確認を維持する。自動許可に対応できない場合も、内容表示と連続確認を減らす代替策を提供する。
- /stop・取消の受付、Run終了、設定変更・復元で失効する。Steerも既存許可の失効と依頼内容世代の更新を伴う。承認ボタン押下は追加発言ではない。次の発言に持ち越さない。
- ツール内フォーム、認証URL、追加権限、秘密入力は自動回答しない。不明な回答の再送・AI再実行で回復しない。
- 正常に許可送信が確認された終了済みMCP確認は、同一依頼の要約カードへまとめる。個別カードは所有確認・送信結果照合後に除去し、DBの操作記録は保持する。拒否・失効・不明は成功にまとめない。resolvedだけを許可やツール成功の証拠にしない。
- 契約未対応のProxyでは今回だけの許可を維持する。現在のAPIで実引数を照合できない場合は、取得できた確認原文と不足を表示し、分からない場合の拒否・/stopを案内する。

受入：同じツール5回の単発/ターン限定の違い、次の依頼・並列Runへの非流用、Steer失効、危険ツール除外、未知のcall対応、フォーム非自動回答、再起動/送信結果不明、カード集約と監査、実MCPと実Discordの確認を含む。常駐自動許可の有効化は具体契約・受入完了後に別途行う。

### 合意契約0.3の接続条件

**現行API 0.3での表示制約：** 操作詳細は requester_only として本人限定画面に表示し、公開チャット・通常ログへ実引数やコードを出さない。表示した内容と許可のrevision/fingerprintを照合する。許可取消は以後の適用停止であり、既に送信中の呼出しの取消や作業停止とは説明しない。browser_evaluateは合意契約0.3でも個別確認のため、連続確認削減の受入は代替の閲覧経路の実証まで未完了とする。具体JSON・フォールバック等の確認は [契約レビュー](mcp-turn-approval-api-review.ja.md) に記録する。

### 最初のカードで判断・承認するUI（方針合意済み）

- **UI-01 表示先と初期表示：** 元のDiscord会話へ、判断に必要な操作説明と選択肢を同じカード・同じ表示版で送る。通常の操作で「操作詳細」を押すことやDMへの移動を必須にしない。説明には実際の操作と対象を含め、単なるツール名や安全性の宣言で代用しない。
- **UI-02 選択肢：** 「この依頼中、このツールを許可」「今回だけ許可」「拒否」を表示する。ターン限定対象外では単発・拒否の2択。まとめて許可する範囲は現在の依頼・同じツール・引数変更を含むことを説明する。許可一覧・取消は `/mcp` に分離し、一覧を許可操作に見せない。
- **UI-03 公開範囲：** Proxyが公開用として提供した情報だけを元の会話へ表示する。利用者は検索語・アクセス先URLなど操作対象を元の会話に表示する方針を明示承認済み。その会話の閲覧者へ見えることを含む。認証情報・秘密入力・任意の実行コードはこの承認に含めず、本人限定補足へ分ける。Proxyはこの方針に対応した評価済みrendererで公開情報を構成し、Gatewayの秘密文字列置換だけで公開可能と判断しない。本人限定の実引数を公開用説明に転用しない。
- **UI-04 例外：** 秘匿・省略・長文・未評価形式などで判断材料が足りない場合は、その理由を最初のカードに示す。例外時だけ本人限定の補足確認へ進む。切り詰めた説明のまま直接許可を有効にしない。取得不能では拒否または `/stop` を案内する。
- **UI-05 表示と承認の一致：** 公開内容、秘匿・省略状態、直接承認可否を実呼出しと対応付ける。表示確認済みの版だけを承認でき、GatewayとProxy双方で押下時に再検証する。別利用者・別会話・古いカード・変更済み内容・失効した実行から許可できない。
- **UI-06 運用：** 本番の常時許可ツールを試験のために確認対象へ変更しない。旧Proxyでは互換経路を維持し、新UIが利用可能とは案内しない。

受入は通常3択・対象外2択、公開不可／長文の例外、公開先の本人限定データ非漏洩、表示前／古いカード／別会話の拒否、送信結果不明・再起動、単発とターンの非混同を含む。具体接続契約は [Proxyの0.4案](../../codex-hoshikage-proxy/docs/mcp-inline-approval-api.ja.md)。公開API・表示トークン・例外形式は [接続レビュー](mcp-inline-approval-api-review.ja.md) で照合済み。操作対象の公開方針とbrowser-find-v1／browser-navigate-v1／browser-tabs-list-v1の引数・表示・除外規則は確定。R-01対応版のGateway接続レビューは完了。方針合意はAPI実装・配備完了を意味しない。

合意API 0.3を接続実装の基準とする。詳細表示・作成・一覧・取消、固定Run対応、schema 7と受入は [Gateway詳細設計](mcp-turn-approval-gateway-design.ja.md) に確定した。/mcpはこの会話の最新作業の許可を本人限定で確認する操作。過去のカードからはその依頼に固定した許可を確認する。公開チャットへ実引数・コードを転記しない。
