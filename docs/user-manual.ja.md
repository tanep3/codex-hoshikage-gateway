# ユーザーマニュアル

[English](user-manual.md) · [製品概要](../README.ja.md) · [導入手順書](installation.ja.md)

準備ができたら、Codexに仕事を頼んでみましょう。最初のメッセージから、相談の続け方、成果物の受け取りまでを案内します。Botや本人・プロジェクトチャンネルの登録がまだなら、先に[導入手順書](installation.ja.md)へどうぞ。

裏側では [Codex Hoshikage Proxy](https://github.com/tanep3/codex-hoshikage-proxy) がCodexにつなぎ、GatewayがDiscordの会話を受け持っています。普段の依頼はDiscordから行えます。

現在の版は許可した本人1人用です。Botのコマンド説明・ボタン・応答は日本語で、コマンド名は以下の英語表記です。開発版0.1.0の実サービス受入試験は未完了です。

## まずは話しかけてみましょう

登録済みのプロジェクトチャンネルに「こんにちは」と投稿してください。同じチャンネルで会話を続けると、そのチャンネルの文脈を引き継ぎます。別のプロジェクトは別のチャンネルで話しましょう。通常は回答本文だけを表示し、依頼ID・COMPLETED・配信完了の通知は付けません。詳しい状態は `/status` で確認できます。

設定は `[discord]` の `response_mode` で選べます。

```toml
response_mode = "all" # 許可本人の全投稿に応答（既定）
# response_mode = "mention" # Botへの明示メンション時だけ応答
```

mentionモードではBot自身をメンションしてください。他ユーザーへのメンションや通知なし返信は対象になりません。スラッシュコマンドはどちらのモードでも利用できます。設定変更後は運用者が `admin reload` で反映します。

未登録の投稿場所では作業フォルダーの登録方法を案内し、Codexの作業は始めません。DM・他サーバー・未許可ユーザーは対象外です。チャンネルを閲覧できる人には回答も見えるので、閲覧権限を確認してください。

独立した会話を追加したいときだけ、親チャンネルで `/new title:会話名` を使えます。既存の登録済みスレッドも引き続き使えます。

## 次の仕事を頼む？ 今の仕事にひとこと足す？

Codexが作業中の通常投稿は、**次の依頼として待機列に入ります**。実行中の作業へ即座に反映される指示ではありません。会話内は順番に実行し、全体では最大2実行、同じ作業フォルダーでは同時1実行です。同じプロジェクトの別会話が待機する場合もあります。

現在の作業へ追加指示を伝えるときは次を使います。

```text
/steer text:まずパーサーを調べてください。公開APIは変更しないでください。
```

Steerは現在の作業だけが対象です。対象となる実行がない場合、承認待ち、中断処理中、終了後には利用できません。指示どおりの動作を保証する機能ではありません。**止めたいときは `/stop` を使います。**

待機中の依頼の元メッセージや添付は編集・削除しないでください。送信前に元入力を再確認するため、変更や取得不能があれば拒否されます。訂正したい場合は、先に状態を確認し、同じ効果を持つ作業を二重に依頼しないようにしてください。

## いったん止めたいときは

```text
/stop
```

先に会話の待機列を一時停止し、実行中の作業があれば中断を要求します。通常は停止ボタンを表示しません。以前の投稿に残っている停止ボタンは利用できます。

- 待機依頼だけなら、実行中断はなく待機列を一時停止します。
- 依頼の送信中で実行IDがまだわからない場合、一時停止は反映されますが、実行停止はまだ確認できません。
- 中断要求の受付は、実行停止の確認とは異なります。後続の状態表示や `/status` を確認してください。
- すでに行ったファイル変更などは元に戻りません。

一時停止中も投稿できます。受理された依頼は待機し、自動では始まりません。待機中の依頼を開始可能に戻すには次を使います。

```text
/resume
```

中断した作業そのものを再開する操作ではありません。続きが必要なら、前の結果を確認して新しい依頼を投稿してください。一時停止はGatewayの再起動後も維持されます。また、`UNKNOWN` による実行保留は `/resume` では解除されません。運用者による確認が必要です。

## 承認を求められたら

Proxyが承認を要求すると、その操作に対応したボタンが表示されます。

| ボタン | 意味 |
| --- | --- |
| 今回のみ承認 | 今回の操作だけを許可する |
| 拒否 | 操作を許可しない |
| 取消 | 承認要求を取り消す |

対象の操作を読んでから選んでください。応答できるのは許可ユーザーだけです。期限切れや対象の変更後は無効になるため、古いボタンではなく現在の要求を使います。恒久的・セッション全体の承認は提供しません。拒否や取消で作業が失敗・停止する場合があるため、最終状態を確認してください。

すべての依頼で承認が出るわけではありません。Proxyの方針とCodexが行おうとする操作によって決まります。

## モデルを変えてみましょう

会話内で `/models` を実行すると、利用可能なモデルを表示します（現在の一覧は最大25件）。表示されたProvider付きIDを指定します。

```text
/model id:PROVIDER/MODEL_ID
```

仮文字列を実際のモデルIDに置き換えてください。Discordで `/model` を選び、`id` の入力欄を開いて値を入れます。通常メッセージにコマンド風の文字列を書く操作ではありません。引数なしの `/model` は選択中モデルの確認です。選択は会話の文脈を保ったまま**次の作業**に適用され、実行中のモデルは置き換えません。選択モデルと現在の作業のモデルは `/status` で区別できます。別Providerへ切り替える場合は新しい会話が必要です。

## ファイルを渡す・受け取る

通常の依頼メッセージに、Discordの添付操作でファイルを付けます。対応する入力は次のとおりです。

- PNG・JPEG・WebPの静止画像。
- UTF-8のテキストファイル。

アニメーション画像、PDFなどの汎用文書解析、アーカイブ展開は入力機能の対象外です。運用者が設定した上限とDiscord側の上限が適用されます。設定例では添付は最大4件、1件8 MiBまで、エンコード後も含めた入力合計は16 MiBまでです。テキストには別途256 KiBの上限があります。運用者が変更している場合もあるので、標準値の一覧は[導入手順書](installation.ja.md)を参照してください。ファイルと依頼はDiscord・Proxyを経由するため、それらへ送る意図のある内容だけを添付してください。

成果物を受け取るには、プロジェクトフォルダーからの相対パスを明示します。

```text
/get path:output/report.pdf
```

これは**サーバー上**に存在するファイルの取得です。スマートフォンや手元のPC内のパスではありません。入力PDFの解析は非対応でも、作成済みPDFの成果物取得は可能です。Botは新規・変更ファイルを自動探索・自動送信しません。Codexの回答にパスが書かれていても、それだけでは取得指示になりません。

絶対パス、プロジェクト範囲外、シンボリックリンク、ハードリンク、特殊ファイル、安全な読取を確認できないファイルは拒否します。設定やDiscordの容量上限でも取得できない場合があります。その場合は適切な小さい成果物を作るよう依頼し、改めて明示取得してください。

## 今、どうなっている？

会話内の `/status` で、一時停止、選択モデル、保留中の依頼、Proxyの準備状態を確認できます。主な依頼状態は次の意味です。

| 状態 | 利用者にとっての意味 |
| --- | --- |
| `QUEUED` | 順番・実行枠・待機再開を待っている |
| `SENDING` | Proxyへ依頼を渡している途中。実行確認前の場合がある |
| `RUNNING` | 実行中 |
| `APPROVAL_REQUIRED` | 本人の判断待ち |
| `CANCEL_REQUESTED` | 中断要求済み。停止確認はまだ |
| `CANCELLED` | 中断を確認済み |
| `COMPLETED` | Codexの実行が完了。Discordへの回答配信とは別 |
| `FAILED` | 作業が失敗。次の依頼前に報告内容を確認する |
| `UNKNOWN` | 実行状態を確実に確認できない。自動再実行を保留する |

待機列へ入る前に入力検証が行われる場合もあります。入力拒否は実行依頼として受理されていない状態です。待機列が満杯なら新しい依頼を受理できません。

## 再起動や接続トラブルのあとに戻ってきたら

同じDiscordチャンネル（旧会話はスレッド）に戻ってください。投稿済みのDiscordメッセージはそのまま残ります。Gatewayは会話の対応と一時停止を保存し、復旧対象の未送信依頼はDiscordから元投稿を再取得して照合します。削除・編集・取得不能の入力を自動実行しません。

到達不明の依頼を自動で再送することはありません。`UNKNOWN` は同じ作業フォルダーの後続実行を保留する場合があり、`/resume` では解除できません。ホストの運用者にGatewayとProxyの状態照合を依頼してください。自分が運用者なら、ローカルの `admin status` と[導入手順書](installation.ja.md)から案内する復旧規則を確認します。

**実行完了と、回答全文を受け取れたことは別です。** 現在のProxy契約には最終回答本文の再取得機能がありません。Gateway再起動や回答メモリの保持期限後には、完了が確認できても欠けた回答本文を復元できない場合があります。Botはその制約を通知し、回答を再現するためのCodex再実行は行いません。プロジェクト内に残っている成果物は、利用可能なら `/get` で個別に取得できます。

最初の作業が失敗・中断すると、継続可能な会話の文脈が残らない場合があります。`NEW_CONVERSATION_REQUIRED` と表示されたら親チャンネルで `/new` を使い、続けたい作業を説明してください。スレッドがアーカイブ・ロックされている場合は、権限があればDiscord上で利用可能に戻すか、新しい会話を作ります。Botが自動で開き直すとは考えないでください。

## コマンド早見表

以下の `名前:値` はDiscordのコマンドオプションを表します。コマンドを選び、表示される入力欄へ値を入れてください。

| 操作 | 場所 | 用途 |
| --- | --- | --- |
| `/new title:会話名` | 登録プロジェクトチャンネル | 会話を作る |
| 通常投稿（添付も可） | 登録プロジェクトチャンネル／既存会話スレッド | 次の仕事を依頼する |
| `/status` | プロジェクトチャンネル／既存会話スレッド | 状態・モデルを確認する |
| `/stop` | プロジェクトチャンネル／既存会話スレッド | 待機を一時停止し、中断を要求する |
| `/resume` | プロジェクトチャンネル／既存会話スレッド | 待機中の依頼の自動開始を再開する |
| `/steer text:追加指示` | プロジェクトチャンネル／既存会話スレッド | 実行中の作業へ指示する |
| `/models` | プロジェクトチャンネル／既存会話スレッド | モデルを一覧する |
| `/model` | プロジェクトチャンネル／既存会話スレッド | 選択中モデルを確認する |
| `/model id:PROVIDER/MODEL_ID` | プロジェクトチャンネル／既存会話スレッド | 次の作業のモデルを選ぶ |
| `/get path:相対パス` | プロジェクトチャンネル／既存会話スレッド | 指定した成果物を取得する |

Botがオフライン、コマンドが出ない、すべて拒否される場合は[導入時の確認事項](installation.ja.md)を参照してください。特定の依頼が結果不明の場合は、同じ仕事を再投稿する前に状態を確認してください。
