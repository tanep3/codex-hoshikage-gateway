# ユーザーマニュアル

[English](user-manual.md) · [導入手順](installation.ja.md)

このマニュアルは、用意済みのBotをDiscordで使う方に向けたものです。Botのインストールやキー設定をする方は[導入手順](installation.ja.md)から始めてください。

## 最初の会話をしてみましょう

1. Botが参加しているDiscordサーバーを開き、使いたいテキストチャンネルへ移動します。フォーラムなら投稿を開きます。
2. 「こんにちは。何ができますか？」と送ってみましょう。メンション時だけ応答する設定なら、入力欄で `@` からBotを選んで話しかけます。
3. 返事が来たら、そのまま続けて質問できます。新しい会話を作るコマンドや、サーバーの作業フォルダーの指定は不要です。
4. 反応しない場合は、入力欄に `/` と入力し、このBotの候補から `/status` を選びます。表示された案内を確認し、解消しなければ管理者へ伝えてください。

このBotは管理者が許可した本人だけが操作できます。ほかのメンバーの投稿へ返事がなくても、故障とは限りません。会話の投稿自体は、そのチャンネルを見られる人にも見えます。

### コマンドの使い方

表の `/model id:モデルID` などは、Discordのコマンド名と入力欄を示しています。入力欄で `/model` を選び、表示された `id` 欄に値を入れて送信します。`モデルID` という文字そのものは入力しません。モデルを選ぶだけなら、引数なしの `/model` でメニューを開く方が簡単です。

## 話しかける

許可されたサーバーの通常チャンネルやフォーラム投稿で話しかけてください。cwdや `/project` の登録は不要です。通常チャンネルはチャンネルごと、スレッドやフォーラムは投稿ごとに会話を持ちます。

Botが全投稿に答えるか、メンション時だけ答えるかは運用設定で選べます。設定済みのモデルを使い、選択が必要なときはモデルメニューを表示します。

## モデルと作業の操作

| 操作 | 使い方 |
| --- | --- |
| `/workspace` | 会話を始める前に共有ワークを選ぶ（通常は不要） |
| `/retry` | 回答／成果物を選び、確認後に同じ保存版を再送 |
| `/get scope:shared` | 明示的に共有ワーク全体の成果物を選ぶ |
| `/models` | 利用できるモデルの一覧 |
| `/model` | 選択中モデルを確認し、メニューから変更 |
| `/model id:モデルID` | 次の依頼からモデル変更。同じProvider内で会話を継続 |
| `/status` | 会話、選択／実行モデル、停止状態、Proxy接続を確認 |
| `/steer text:追加指示` | 今動いている作業へ追加指示。通常投稿は次の依頼として待機 |
| `/stop` | 待機列を一時停止し、受付済みの依頼を停止。開始前でも操作可能 |
| `/cancel` | 直近の待機依頼を1件取り消す。待機がなければ実行中の依頼を停止。待機列の一時停止状態は変えない |
| `/resume` | 待機列を再開。停止した依頼をやり直す操作ではない |
| `/new title:会話名` | 任意：別のスレッド／フォーラム投稿をBotに作らせる |
| `/mcp` | この作業中のMCP許可を確認・取消。作業全体の停止は `/stop` |

停止の受付と、実際に停止したことは別です。確認できない場合は不明と案内します。承認が必要なときは、表示された対象と内容を確認してボタンで回答してください。

## ファイルを渡す・受け取る

画像やUTF-8テキストは投稿に添付できます。容量上限を超えた入力は実行しません。

`/get`を開くと登録済み成果物を選べます。モデルの専用登録ツールで保存されたファイルが対象です。未登録のファイルは `/get path:output/report.pdf` のように相対パスで指定できます。絶対パスは不要です。

選んだファイルは、Proxyがその時点で保存した版です。同じ版の再送と、更新後の原本から新しい版を作る操作を区別します。一覧は25件ずつ「次のページ」で進めます。選択画面は10分間有効です。期限が切れたら `/get` で開き直してください。配信のやり直しは `/retry` で選び、重複の可能性を確認してから実行します。AIの作業はやり直しません。

## 接続が切れたら

Gatewayの接続切断だけではProxyの実行は止まりません。停止したいときは `/stop` を使います。確定回答と成果物はProxyの保存期限内で再取得し、Gatewayのキャッシュが消えても同じIDを使います。保存失敗・期限切れ・権限撤回では回収できない場合があります。AIを自動再実行して回答を作り直すことはありません。

実行状態が不明なら通常操作で解除せず、運用者がProxyを確認します。復元世代が変わった場合も管理照合が必要です。管理者向けの復旧手順は[運用ガイド](operations.ja.md)を参照してください。

## ファイルを共有して作業したいとき

通常は会話ごとに専用の作業先が用意されます。別の会話とファイルを共有したい場合だけ、最初に話しかける前に `/workspace` で候補を選んでください。configやホストのパスを登録する必要はありません。共有ワークでは、別の会話からの変更も見えます。

すでに作業先が決まっている会話は変更できません。別の作業先を使いたい場合は、Discordで別の投稿を作り、そこで選んでください。フォーラム内なら同じフォーラムに新しい投稿ができます。タグ必須のフォーラムはDiscordの「投稿を作成」を使ってください。

[運用ガイド](operations.ja.md)

いつもの場所で普通に話しかければ会話を受け付けます。`/new` は会話を始めるための必須操作ではありません。

## 画像を作ってもらう

普通に「画像を作って」と頼めば、対応Proxyが登録したPNGを同じ会話へ自動で添付します。文章なしでも届きます。`/get` は不要です。画像の登録に時間がかかる場合は、文章より後に届きます。失敗・中断した作業でも保存できた画像は届け、送信前に中断が分かった場合は途中成果と表示します。

`/get` は配信待ち・配信済みの保存版を重複添付しません。もう一度受け取りたいときは `/retry` で確認して再送します。容量超過や保存期限切れは `/get` でも回避できません。追加のconfig設定は不要です。

画像の準備や送信に時間がかかると、Botが進捗を表示します。同じ案内が配信完了・画像なし・問題発生の表示へ更新されるので、そのままお待ちください。

通常の作業中・完了だけを知らせる投稿は追加しません。一時的な状態確認の警告は、正常な状態を確認できたら自動で削除します。

## 承認と作業中の表示

許可が必要なときは、目的と実行内容を示すカードが出ます。「今回のみ承認」は表示された操作だけを許可します。承認・拒否・取消後は同じカードからボタンが消え、結果を表示します。送信確認中は再度押さず、その会話でお待ちください。

作業中はDiscord標準の「入力中…」が表示されます。承認待ち・完了・状態不明の間は更新を止めます。Discord側の表示は更新停止から最大約10秒残る場合があります。これは処理中の目印であり、内部の思考内容を表示するものではありません。

回答途中の表示は一時表示です。確定した回答は会話の末尾に新しく届き、その後に途中表示を削除します。承認カードより上の古い投稿を探し直す必要はありません。

承認ボタンを押した後は元のカードで結果を確認できます。同じ内容の自分専用メッセージは追加しません。

### MCPツールから確認が届いたら

MCPは、ブラウザーなどの外部ツールをCodexから使うための仕組みです。ここでの「許可」はツール操作を認めることで、ログイン用の認証とは別です。

MCPツールの利用に確認が必要な場合、操作内容と選択肢を表示します。「今回だけ許可」は表示された呼出し1回だけを許可します。対象ツールでは「この依頼中、このツールを許可」も選べます。詳しい範囲は下の「MCPの確認が繰り返されるとき」を確認してください。許可後、ツールから追加の入力フォームが届くこともあります。

フォームは「入力フォームを開く」から項目を選び、「入力する」で記入します。選択肢がある項目は表示された番号、真偽値は「はい／いいえ」を入力します。長文は続きの欄も使えます。最後に「この内容で送信」を押してください。既定値は自動入力しません。入力画面は本人専用で、回答は公開チャットへ投稿しません。Bot再起動後は未送信の入力をやり直してください。

作業を止める場合は `/stop`。期限切れ・送信結果不明の場合は勝手に許可や再送をせず、カードと `/status` に状態を表示します。「回答をMCPへ送りました」はツールの成功通知ではありません。作業結果は続く回答で確認してください。

## 回答・ファイルが届かないとき

- **取得を自動確認中**：同じ依頼を送り直さず、まずお待ちください。数分たっても届かなければ `/status` の結果と案内メッセージを運用者へ伝えてください。
- **Discordへの送信結果が不明**：この会話に届いているか確認してください。届いていれば操作不要です。届かず再送したい場合は `/retry` で対象を選び、重複の可能性を確認して再送できます。同じ保存版を送る操作で、AIの作業はやり直しません。
- **権限・容量・破損・期限切れ**：案内された原因への対処が先です。再送だけでは直りません。設定や保存領域は運用者に確認を依頼してください。期限切れのファイルは原本が残っていれば `/get path:...` で新しい保存版を取得できますが、回答テキストはこの方法では復旧できません。

配信完了後、古い取得警告は自動で削除します。警告自体の送信・削除結果が不明な場合は、照合できるまで残ることがあります。

### MCPの確認が繰り返されるとき

同じサーバー・ツールでも、別の呼出しごとに確認が届く場合があります。「今回だけ許可」はその1件だけです。確認原文と実際の引数・コードを照合できない場合は、その不足を表示します。内容が分からないまま許可せず、「拒否」を選ぶか、作業全体を止めるなら `/stop` を使ってください。

許可送信と確認の終了を確実に確認できたカードは、同じ作業の件数表示へまとめます。件数は許可・フォーム回答の送信記録であり、ツールが成功したという意味ではありません。拒否・期限切れ・結果不明の案内は残します。

対応するGatewayとProxyで機能が有効なら、ページ内検索やページ移動などは、**最初のカードに操作内容と検索語・URLが表示されます**。内容を読んで、その場で次のいずれかを選んでください。

- **この依頼中、このツールを許可**：同じ依頼で同じMCPサーバーの同じツールを繰り返し使うことを許可します。後続の呼出しでは引数や操作対象が変わる場合もあります。追加指示、停止、依頼の終了で失効し、次の依頼には引き継ぎません。実際のツール呼出しを照合できる場合だけ表示されます。
- **今回だけ許可**：表示された呼出し1回だけを許可します。次の呼出しでは再び確認されることがあります。
- **拒否**：この操作を許可しません。依頼全体を止めたい場合は `/stop` を使います。

検索語やURLは、この会話を閲覧できる人にも見えます。認証情報・秘密入力・実行コード、未対応の操作、長すぎる内容は最初のカードへ載せず、理由と「本人限定で確認」を表示します。この場合だけ補足画面を開いて確認してください。長い内容は「次へ」で読めます。内容を取得できない場合は許可せず、「拒否」か `/stop` を選び、解消しなければ運用者へ相談してください。古いProxyや更新前から続く依頼では、従来の「操作内容を確認」から本人限定画面を開く方式になる場合があります。

依頼中の許可は**同じツールの引数変更を含む許可**で、特定サイトや読取り操作だけに限定されません。最大10分・この依頼の終了まで有効で、停止やSteerの追加指示で失効します。次の依頼へ引き継ぎません。`browser_evaluate` と `browser_run_code_unsafe` は毎回個別確認です。

`/mcp` で最新の依頼の許可を確認・取消できます。取消は今後の適用を止めますが、実行済みの操作は戻しません。取消結果が不明な場合は一覧を開き直してください。元の取消を照会し、別の要求として送り直すことはありません。

この機能には、管理者によるProxy側の有効化と対象ツールの設定が必要です。更新だけではONになりません。利用者は設定ファイルを編集せず、選択肢が出ない場合は管理者へ確認してください。[Gatewayの導入手順](installation.ja.md)と、Proxyの[利用者・管理者ガイド](https://github.com/tanep3/codex-hoshikage-proxy/blob/main/docs/mcp-turn-approval-guide.ja.md)に設定方法があります。未対応・無効な環境では従来の個別確認を使います。

`/cancel` は取り消した元の投稿を案内します。待機が複数あれば、新しいものから1件ずつ取り消します。実行中の停止は確認が取れるまで保留となり、実行済みの変更は元に戻しません。`/stop` で一時停止した待機列は、必要に応じて `/resume` で再開してください。
