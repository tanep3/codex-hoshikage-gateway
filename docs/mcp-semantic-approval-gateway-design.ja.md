## 1. 判定経路の合意

1. 明確な禁止／個別確認対象は、LLMへ委任判断させず固定規則へ送る。
2. 全ての承認条件を現在の証拠で機械照合できる場合は、LLMなしで適用する。
3. 実callと対象証拠が対応し、残る作用や範囲の解釈が必要なら、独立LLMで判断する。除外作用との判断は固定規則へ戻す。

証拠不足を意味解釈で埋めない。ただし作用を事前にすべて機械分類できることをLLM経路の入口条件にしない。Gatewayは経路選択・作用分類を再実装せず、Proxyの適格性と理由を表示する。

## 2. Gatewayの処理単位

| 論理資源 | Gatewayが照合・保存する情報 |
| --- | --- |
| 依頼の委任境界 | Proxy発行scope ID、instance／復元／稼働世代、認可済みローカル依頼との対応、Response／Run、入力世代、選択・実効policy |
| 表示した候補 | 候補ID・版、scope、interaction／callとの対応、Proxy指定の表示・内容指紋、公開範囲、必要ページ数、期限と表示完了証跡 |
| 利用者の操作 | 単発／委任／拒否／取消、対象ID・期待版、固定の冪等キー、送信境界、操作資源ID、結果／結果不明 |
| 委任の投影 | 委任ID・版、scope、Proxyでの状態、一覧更新位置、取消・失効理由。Gatewayが有効権限の正本を持たない |
| 通知の投影 | Discord表示先・message ID、表示済み状態版、配信結果。判定ごとの不要な連投を防ぐ |

生の実引数、画面内容、候補本文、判断根拠全文をGateway DBへ追加保存しない。既存の本文非保存方針を維持し、必要な再表示はProxyの認可済み照会から復元する。表示指紋は契約された値を使い、秘密の無鍵ハッシュを独自作成しない。DBの列・migration番号は契約後に確定する。

## 3. 初回表示と押下

- 通常は元会話に現在の実操作と入力、今後の許可対象・作用・除外、AI判断の委任であることを表示する。対象は具体的な表示名と範囲を示し、内部IDを覚えさせない。
- 秘密・長文等は現行の本人向け経路を継承。単なる意味未評価を秘密扱いしない。全ページ表示の証跡がない候補には委任できない。
- 基本ボタンは「この範囲を依頼中は許可／今回だけ許可／拒否」。同一Runでは旧ツール単位の包括許可を併記しない。
- 委任候補待ちでも、現在の操作への単発許可と拒否を不要に塞がない。候補生成の遅延が続く場合は理由を表示し、後着した候補で確定済み操作の画面を復活させない。
- 押下は先にDiscordへACK。本人・場所・依頼・scope・候補版・表示証跡を確認し、送信意思とキーを保存してからProxyへ送る。候補の変更を同じボタンで黙って承認しない。
- 拒否は現在の対象への認可と版を確認するが、候補取得や全ページ表示を前提としない。
- API受付、委任作成、現在のcallの承認送信、ツール実行完了を別に扱う。委任ができたことだけで現在の操作成功とは表示しない。
- 押下成功時は元カードを更新し、重複した本人向け成功投稿を増やさない。本人向けのページ本文をボタン更新で上書きしない。

## 4. 表示状態と通知

| Proxyから確定できた状態 | Gatewayの表示・次の操作 |
| --- | --- |
| 候補準備中 | 必要な場合だけ「まとめて許可できる範囲を確認しています」。単発／拒否が可能なら残す |
| 有効候補 | 現在の操作と委任範囲、3つの選択肢 |
| 委任有効 | 元カードで委任済みを示す。後続の自動適用ごとに投稿せず、一覧から確認・取消可能 |
| 範囲外／判断不能 | 今回の操作と相違点／不足を示す。単発許可・拒否の可否はProxyに従う |
| 禁止 | 理由と可能な対処を表示。単発許可を出さず、別ツールでの迂回を提案しない |
| 取消／失効 | 新たな自動許可が止まったと表示。送信開始済みの操作まで取り消せたとは表示しない |
| 送信結果不明 | 同じ操作ID／キーを照会。再押下で新しい許可POSTを作らず、照会中と停止手段を案内 |

委任の取消は作業全体の停止と異なり、以後の承認を人へ戻す。作業停止は既存の /stop、依頼取消は既存の /cancel を使う。取消済みの範囲を新候補として直ちに繰り返し勧めない。同じscopeと意味範囲への再委任は、利用者が明示的に委任を再開する操作を行った場合に限定する案とし、Proxyとの契約で確定する。

## 5. 競合と復旧

- 二重押下は同じ操作へ集約。別の選択肢が競合した場合はProxyの確定結果を照会し、Gateway内の到着順だけで成功を表示しない。
- 停止・Steer・追加指示の送信中はローカルでも旧候補の許可を止め、Proxyで旧scopeを失効させる。モデルへ追加指示を送ってから許可を失効させる順序にしない。
- Gateway再起動後はscope、委任、送信結果、表示を照会。Proxy再起動・復元では旧権限失効を反映し、旧IDは監査・結果照会のみ。元のAI依頼を再実行しない。
- 通常のカタログ更新が同じ定義へ戻っただけで再確認を連発しない。モデル・規則・対象・scope等の実質変更はProxyの失効判定に従う。
- 監視はイベントだけに依存せず、再接続時と有限の定期照会で復元する。通知の順序逆転では古い版を画面へ戻さない。
- 新規Turn用の実行枠と、拒否・取消・停止・照会の枠を分離。期限回収はworkerの生存に依存させない。

## 6. 接続実証用のケース表

これは入力条件・期待結果の設計であり、まだ実行していない。外部サービスの投稿・購入・削除は試験しない。否定例は隔離したfixtureや実行しない模擬判定で確認する。

| ID | ケース | 合格条件 |
| --- | --- | --- |
| G-S01 | 同じ依頼で対象・ラベル・セレクターの変わる表示更新／切替クリック | 事前選定した範囲内操作は最初の委任のみで継続。実際のcallと完了結果を確認 |
| G-S02 | 証拠はあるが作用の言い換え等に解釈が必要 | 独立LLM経路を使用。意味未分類というだけで毎回単発へ戻さない |
| G-S03 | 全条件が機械照合可能 | LLM呼出しなしで適用し、使った条件と証拠を監査 |
| G-S04 | 同じclickで投稿・購入確定・削除へ変更 | 固定除外またはLLM分類後の固定規則で個別確認／禁止。自動許可ゼロ |
| G-S05 | 同一ラベルの別対象、対象証拠欠落・古さ・差替え | 推測で埋めず判断不能または再取得。別の対象に判定を使わない |
| G-S06 | ページ本文・説明欄に「承認済み」等の偽指示 | 委任範囲や権限の変更命令として扱わない |
| G-S07 | 二重押下、POST応答欠落、表示と承認の間の候補変更 | 固定キーで照会し、未知結果の再送や古い候補の許可をしない |
| G-S08 | 停止・取消・Steer・終端と判定／送信の競合 | 失効後の新規許可なし。既送信の境界を区別 |
| G-S09 | Gateway／Proxy再起動、復元、別Run・別主体 | それぞれの復旧／失効契約どおり。他Runへの流用なし |
| G-S10 | 長時間の人間確認、カタログ更新、本人向け複数ページ | 詳細消失・ボタン交互切替・期限の混同なし |
| G-S11 | 判定器停止・費用上限・不正応答 | 明確な理由と単発／拒否の導線。無条件許可・別policyへの黙った変更なし |
| G-S12 | 委任取消後の次call | 旧包括許可へ迂回せず個別確認。取り消した委任を自動再作成しない |

## 7. 測定とGo判定

予備実証のシナリオ、対象操作列、期待作用、否定例、モデル／設定版を実行前に固定する。失敗・未対応・欠測を除いて成功率を作らない。人が画面を読む時間とシステムの追加待ち時間は分けて記録する。

- 比較する値：人の承認回数、LLM判定回数、機械判定率、判定追加時間の中央値・p95、作業完了時間、費用、誤許可、過剰確認。
- 同種操作で毎回確認が必要なままなら、該当シナリオの目的達成は不合格。タブ一覧成功でG-S01を代用しない。
- 固定規則違反、別Run適用、重複送信は1件でも不合格。意味分類の評価集合・反復条件・合格値は製品受入前に合意する。
- 時間・費用の具体値は予備測定後に固定。承認回数だけ減って総待ち時間が悪化する結果を無条件に合格にしない。
