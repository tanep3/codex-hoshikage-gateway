# Proxyへの修正・契約調整依頼：MCP承認の全体是正

2026-09-17。調査結果と修正要求。新しいAPIや許可設定が合意・実装済みという意味ではない。

## 結論

利用者は、通常のMCP操作について最初のDiscordカードに「何を実行するか」を表示し、「この依頼中、このツールを許可／今回だけ許可／拒否」をその場で選ぶことを要求している。browser_tabsだけ直して終了にしない。Gatewayが0.4を全体の完成として案内したことは不適切だった。

全342ツールの確認表と証拠は [全体監査](mcp-approval-full-audit.ja.md) を参照。

## 最優先：正常な公開表示が失われる共通不具合

- 実要求：browser_tabs、arguments={"action":"list"}、binding_status=verified。
- 常駐API：presentation=private_required、reason=unsupported_renderer。別条件としてturn_grant_eligible=false、ineligible_reason=tool_not_allowlisted。
- 同じ生成configを使う隔離App Serverから、codex_apps 272、playwright 43、serena 23、node_repl 4、合計342ツールを取得。
- カタログをUTF-8 compact JSONに再構成して1,076,442 bytes。Proxyのrefresh_catalogの1,048,576 bytes制限を超える。Playwright自体は28,877 bytes、tabsのschemaは現コードの条件と一致。
- refresh_catalogはサイズ超過・10秒timeout・RPC失敗等をnullへ統合し、register_catalogで全定義を空にする。その後のpermitted=falseがunsupported_rendererになる。
- 実全カタログ取得は9.09秒、常駐presentation照会でも約10秒を観測。常駐内部の当該RPC本文・timeout原因を直接記録してはいないので、全発生がサイズ超過かtimeoutかは断定しない。

必要対応：

1. 本番と同じ全MCP/Appsを含むカタログで、対象ツールが正常認識されるよう修正。有限上限・ページング・対象抽出・メモリ上限を明文化する。単に無制限にしない。
2. 取得失敗／サイズ超過／定義不一致／未対応形式を区別して機械可読に返す。Gatewayの理由enum検証と表示も同じ契約改訂で対応する。
3. presentation取得ごとの全件同期照会・同時要求・キャッシュ失効・設定変更・復元世代を整理する。取得失敗を理由に未検証の古い定義で許可してはいけないが、「未対応」と偽ってもいけない。
4. 通常のfind/navigate/tabs-listが理由なく補足へ落ちた試験を合格扱いしない。全カタログサイズ超過・遅延・復帰・並列照会を回帰へ追加する。

## 全ツールのUIとターン許可を整理する

現契約は3 rendererだけで、その他は秘密がなくても補足となる。ProxyとGateway双方の対応範囲不足として扱う。

- 全ツールについて操作説明・対象・変更有無・秘密の所在・許可範囲・判断材料を確認する。
- 通常操作は初回カードで判断可能にする。任意の生JSONの公開で代用せず、実呼出しとの対応・公開安全性をProxyが保証する。
- 未対応・一時取得不能と秘密情報を含む例外を区別する。例外でも公開できる操作概要を最初に示す。
- 本番のターン許可対象は現在browser_findだけ。利用者が求める3択が対象外設定で消える状態を、単なる設定説明で終了させない。各ツールの適格性と運用設定を一緒に提示する。
- browser_tabsはlist/new/close/selectの複合ツール。現行turn_toolは引数変更を含み、listだけの許可ではない。対象追加を行う際にはこの範囲を表示する。操作別に絞るなら追加scope契約が必要。
- 任意コード実行、秘密入力、内部認証フォームの例外方針は維持する。包括的な自動許可へ暗黙昇格させない。

## 責務

Proxyはカタログ・実呼出し同定・公開投影・適格性・許可適用と失効を担当。Gatewayは本人・送信先・初回カード・選択・配信版照合・復旧を担当。Proxyのrequester_onlyをGatewayで無視して公開しない。Gateway側のコマンド／ファイル承認の省略問題はGatewayで別途是正する。
